# Учёт устройств: сервер обновлён, клиент готовится к выпуску

Одна физическая группа занимает один слот; приложения внутри связываются владельцем явно. Модель, IP и версия приложения не являются доказательством одного устройства. При миграции каждая существующая установка остаётся отдельной группой. Существующие ключи, имена, запреты и лимиты сохраняются.

Привязка уже известных установок выполняется через `device-action/link`. Для нового клиента `device-action/pair` выдаёт одноразовую ссылку на 10 минут. Её импортируют на том же устройстве; новый HWID получает существующий физический идентификатор до проверки квоты. Повторная загрузка уже зарегистрированного клиента сохраняет доступ после истечения ссылки. Отделение клиента проверяет наличие отдельного слота. Отключение/удаление карточки охватывает все её приложения.

Нативная служба передаёт состояние VPN при включении/выключении и каждые 15 секунд. Подтверждение истекает через 45 секунд, если приложение или сеть исчезли без финального сообщения. Исторический трафик не означает текущее подключение. Нет достоверных наблюдений — отдельный статус «Нет данных». Видимый список опрашивается через 5 секунд после предыдущего ответа, без перекрывающихся опросов; скрытый экран не опрашивается.

Перед выпуском согласованно применить миграцию `20261025010000_physical_device_groups.sql` из серверного проекта и обновить `cabinet-api` и `subscription-link` с общими модулями, затем выпустить APK. Владелец разрешил выпуск обновления; миграция и серверные функции применены после проверки резервной копии и отсутствия изменений флагов доступа.

Тесты PostgreSQL выполняются в изолированной PGlite-базе в серверном проекте (`scratch/device-groups-sql.test.cjs`), а не в рабочей базе. Проверяются квота, явное объединение, разъединение, истечение/повтор ссылки, запреты и разделение аккаунтов.
