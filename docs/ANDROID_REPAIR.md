# Android: восстановление и соответствие Windows-клиенту

База: `AndreyViht/viht-vpn-android`, commit `4cc1ac425ab16f692357a6e59da552e8c1e8026f`. Исходники Kotlin и workflow в восстановленной папке совпадают с этой версией GitHub.

Цель: тот же интерфейс Liquid Glass и тот же аккаунт VihtVPN, при этом VPN работает через Android VpnService/libbox, без симуляции подключения и без предустановленных чужих ключей.

- Исходники интерфейса находятся в `web/`; APK содержит результат их сборки в assets, а не вручную исправляемый минифицированный JS.
- Авторизация: только Яндекс ID и VK ID; локальный callback с одноразовым state, проверка owner JWT и обновление refresh token. Сессия хранится через Android Keystore.
- Список ключей: фактическая подписка с HWID телефона, пустой список не заменяется заглушками. TCP-пинг выполняется реально и не подменяется фиксированными числами.
- WebView открывает только локальные assets. Внешняя авторизация и ссылки открываются в браузере без доступа к native bridge.
- Android разрешает VPN через системный диалог. Блокировка соединений без VPN — отдельная системная настройка Android, её нельзя имитировать переключателем приложения.
- Физическая проверка соединения, переходов Wi-Fi/LTE и поведения при блокировке экрана выполняется владельцем на телефоне.
- Тестовая сборка должна публиковаться как Actions artifact, без перезаписи существующего публичного релиза.

Нативное ядро и его checksum сохраняются из проверенного upstream-артефакта. Публичный репозиторий не должен содержать access tokens GitHub, учётные данные пользователей или приватные ключи подписи.
